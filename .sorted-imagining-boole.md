# Game Widget System Extension Plan

## Overview

Extend tulip.arke.me's widget system with game-oriented widgets for async RPGs, MUDs, and interactive fiction. Build incrementally on existing architecture without over-engineering.

## Key Design Decisions

### 1. Session State: Bot-Managed (Not Meta-Widget)
- Bot maintains session state via existing `Arc<RwLock<HashMap<topic, state>>>` pattern
- Frontend remains stateless - just renders current widget
- History preserved naturally via SubMessage rows
- No new "session" widget type needed

### 2. Shared Components via Handlebars Partials + CSS
- Create `web/templates/widgets/game_components/` for reusable partials
- Create `web/styles/widgets_game.css` for game-specific styling
- Namespace all game CSS under `.widget-game-*`

### 3. Minimal First-Class Widget Types
- Add only 4-5 new widget types max
- Use `freeform` for experimentation (Rhai tooling, etc.)
- Promote to first-class only when patterns stabilize

### 4. Composition Over Multiplication
- Build small partials (portrait, resource_bar, exit_button)
- Compose into widgets (dialogue = portrait + text + choices)
- Avoid N widget variants

## Phase 1: Foundation + Dialogue Widget

**Goal**: Enhanced spweens with proper dialogue UI.

### Files to Create

**`web/src/dialogue_widget.ts`**
```typescript
// Schema
const speaker_schema = z.object({
  name: z.string(),
  portrait_url: z.optional(z.string()),
  mood: z.optional(z.string()),
});

const choice_schema = z.object({
  label: z.string(),
  custom_id: z.string(),
  disabled: z.optional(z.boolean()),
  requirement_text: z.optional(z.string()), // "[Requires 10 STR]"
});

export const dialogue_extra_data_schema = z.object({
  speaker: z.optional(speaker_schema),
  text: z.string(),
  choices: z.optional(z.array(choice_schema)),
  continue_custom_id: z.optional(z.string()), // Simple continue button
  history: z.optional(z.array(z.object({
    speaker: z.optional(z.string()),
    text: z.string(),
  }))),
});
```

**`web/templates/widgets/dialogue_widget.hbs`**
- Portrait on left (if speaker has portrait_url)
- Speaker name header
- Text bubble with dialogue
- Expandable history section (if history provided)
- Choice buttons below

**`web/templates/widgets/game_components/portrait.hbs`**
- Circular avatar with mood indicator
- Fallback to initials if no image

**`web/styles/widgets_game.css`**
- `.widget-game-portrait` - avatar styling
- `.widget-game-dialogue-bubble` - speech bubble
- `.widget-game-choice-button` - styled choice buttons
- `.widget-game-requirement` - dimmed requirement text

### Files to Modify

- `web/src/widgets.ts` - Add `widgetize.widgets.set("dialogue", dialogue_widget)`
- `web/src/widget_schema.ts` - Add `z.object({widget_type: z.literal("dialogue"), extra_data: ...})`
- `zerver/lib/validator.py` - Add `"dialogue"` to valid widget types with schema check

## Phase 3: Combat + Dice Widgets

**Goal**: Turn-based combat with visual dice rolls.

### dice_roll Widget

```typescript
export const dice_roll_extra_data_schema = z.object({
  rolls: z.array(z.object({
    dice: z.string(), // "d20", "2d6"
    results: z.array(z.number()),
    label: z.optional(z.string()),
  })),
  modifier: z.optional(z.number()),
  total: z.number(),
  target: z.optional(z.number()), // DC/AC
  success: z.optional(z.boolean()),
  flavor_text: z.optional(z.string()),
});
```

### combat Widget

```typescript
export const combat_extra_data_schema = z.object({
  title: z.optional(z.string()),
  participants: z.array(z.object({
    id: z.string(),
    name: z.string(),
    portrait_url: z.optional(z.string()),
    team: z.optional(z.string()), // player, enemy, ally
    hp: z.object({ current: z.number(), max: z.number() }),
    is_current_turn: z.optional(z.boolean()),
    status_effects: z.optional(z.array(z.string())),
  })),
  actions: z.optional(z.array(z.object({
    label: z.string(),
    custom_id: z.string(),
    disabled: z.optional(z.boolean()),
    disabled_reason: z.optional(z.string()),
  }))),
  log: z.optional(z.array(z.string())),
});
```

## Phase 4: Inventory + Character Sheet

Use `freeform` widget initially. Promote to first-class if patterns emerge.

These are more complex and benefit from iterating with HTML/CSS/JS first.

---

## Phase 5: Rhai Developer Tooling

**Goal**: Script editor, REPL, inspector for game creators.

Keep as `freeform` widgets:
- Embed CodeMirror or Monaco for syntax highlighting
- REPL with command history
- State tree inspector

These are power-user features where flexibility matters more than validation.

## Complexity Guardrails

1. **Max 5 first-class game widgets** - dialogue, room, dice_roll, combat, (one more TBD)
2. **Freeform for experiments** - inventory, character sheet, dev tools start as freeform
3. **Shared partials** - portrait, resource_bar, etc. used across widgets
4. **No widget variants** - compose components, don't multiply widget types
5. **Bot manages complexity** - session state, history, phase transitions live in bot code
